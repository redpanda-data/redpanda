# macOS Cross-Compilation Work Log

## Goal
Get `bazel build --config=macos-linux //:redpanda` working 100% on macOS

## Root Cause Analysis
**Problem**: When `--cpu=k8` is set (Linux x86_64), some C/C++ libraries are still compiled for macOS instead of Linux.

**Why**: The Rust `supported_platform_triples` in MODULE.bazel includes macOS platforms (lines 388-389):
```python
"aarch64-apple-darwin",
"x86_64-apple-darwin",
```

This affects Bazel's global platform resolution, causing some targets to default to exec platform (macOS) instead of target platform (Linux).

## Key Learnings

1. **toolchains_llvm limitations**: Doesn't easily support local LLVM + remote sysroots
2. **Platform resolution is global**: Adding macOS to Rust platforms affects all targets
3. **--cpu alone isn't enough**: Need proper platform configuration
4. **Bazel toolchain selection is complex**: Exec vs target platform interactions
