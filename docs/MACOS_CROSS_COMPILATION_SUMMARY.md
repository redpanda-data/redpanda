# macOS to Linux Cross-Compilation - Implementation Summary

## Approach: Pre-Built Local Toolchains

Instead of building custom LLVM toolchains from scratch, we use **locally-installed LLVM** via Homebrew or system clang, inspired by [Zig's cross-compilation approach](https://andrewkelley.me/post/zig-cc-powerful-drop-in-replacement-gcc-clang.html).

### Why This Approach?

1. **Fast Setup**: 5 minutes vs 2+ hours to build custom toolchains
2. **Easy Maintenance**: `brew upgrade llvm@20` vs rebuilding and uploading toolchains
3. **Proven Pattern**: [Zig successfully uses this approach](https://ziglang.org/learn/overview/), [toolchains_llvm supports it](https://github.com/bazel-contrib/toolchains_llvm/issues/20)
4. **Flexible**: Works with Homebrew LLVM, system clang, or custom builds

## How It Works

```
┌─────────────────────────────────────────────┐
│ macOS Developer Machine                     │
│                                             │
│ ┌─────────────────────────────────────┐   │
│ │ Homebrew LLVM@20 or Xcode Clang     │   │
│ │ /opt/homebrew/opt/llvm@20/          │   │
│ │                                     │   │
│ │ • clang/clang++ (Mach-O binaries)  │   │
│ │ • Generates Linux ELF outputs      │   │
│ │ • Cross-compile to x86_64/aarch64  │   │
│ └─────────────────────────────────────┘   │
│              │                              │
│              ↓                              │
│ ┌─────────────────────────────────────┐   │
│ │ Hermetic Ubuntu 22.04 Sysroot       │   │
│ │ (Downloaded by Bazel)               │   │
│ │                                     │   │
│ │ • glibc headers/libraries           │   │
│ │ • Linux system headers              │   │
│ │ • C++ standard library              │   │
│ └─────────────────────────────────────┘   │
│              │                              │
│              ↓                              │
│      Linux ELF Binary                       │
│      (Runs on Linux)                        │
└─────────────────────────────────────────────┘
```

## Implementation

### Files Created

1. **`bazel/toolchain/setup-macos-toolchain.sh`**
   - Automated setup script
   - Checks for/installs Homebrew LLVM
   - Creates `user.bazelrc` with local config

2. **`bazel/toolchain/MACOS_TOOLCHAIN_OPTIONS.md`**
   - Documents 5 different approaches
   - Compares pros/cons of each
   - Recommends hybrid strategy

3. **Updated Documentation**:
   - `docs/BUILDING_ON_MACOS.md` - Complete developer guide
   - `README.md` - Quick start instructions
   - `bazel/toolchain/README.md` - Toolchain details

### Files Modified

1. **`MODULE.bazel`**
   - Added comments about macOS cross-compilation
   - Kept Linux toolchain configs unchanged
   - No Darwin toolchain downloads (uses local instead)

2. **`.bazelrc`**
   - Added `--config=macos-linux` for x86_64 target
   - Added `--config=macos-linux-arm64` for ARM64 target
   - Added `--config=macos-release` convenience alias

3. **`user.bazelrc`** (generated by setup script)
   - Git-ignored local configuration
   - Points to Homebrew LLVM location
   - Defines `-local` config variants

## Usage

### One-Time Setup

```bash
# Install Homebrew LLVM (or use system clang)
brew install llvm@20

# Run setup script
./bazel/toolchain/setup-macos-toolchain.sh
```

This creates `user.bazelrc`:
```bash
build:macos-local --action_env=CC=/opt/homebrew/opt/llvm@20/bin/clang
build:macos-local --action_env=CXX=/opt/homebrew/opt/llvm@20/bin/clang++
build:macos-local --action_env=PATH=/opt/homebrew/opt/llvm@20/bin:$PATH

build:macos-linux-local --config=macos-local
build:macos-linux-local --config=macos-linux

build:macos-linux-arm64-local --config=macos-local
build:macos-linux-arm64-local --config=macos-linux-arm64
```

### Building

```bash
# Build Linux x86_64 binary
bazel build --config=macos-linux-local //:redpanda

# Build Linux ARM64 binary
bazel build --config=macos-linux-arm64-local //:redpanda

# Build release
bazel build --config=macos-release --config=macos-local //:redpanda
```

### Testing

```bash
# Verify it's a Linux binary
file bazel-bin/src/v/redpanda/redpanda
# Expected: ELF 64-bit LSB executable, x86-64

# Run in Docker
docker run --rm -v "$PWD:/work" -w /work ubuntu:22.04 \
  ./bazel-bin/src/v/redpanda/redpanda --version
```

## Alternatives Explored

### Option 1: Build Custom Toolchains (Original Plan)
- ❌ 1-2 hours per architecture
- ❌ 4 toolchains to build and maintain
- ❌ ~2GB upload to GitHub releases
- ✅ Full control over configuration

### Option 2: Use Official LLVM Releases
- ❌ No macOS binaries for minor versions (20.1.8, 21.1.6)
- ❌ Only major releases sometimes have macOS builds
- ❌ Large downloads (~800MB)

### Option 3: Use Homebrew LLVM (Selected)
- ✅ Easy install: `brew install llvm@20`
- ✅ Pre-built and optimized for macOS
- ✅ Regular updates
- ✅ ~600MB one-time download
- ✅ Local, no Bazel download needed

### Option 4: Use System Clang
- ✅ Already installed (Xcode)
- ✅ Zero setup
- ❌ Version tied to macOS/Xcode
- ❌ May have Apple-specific patches

### Option 5: Use Zig
- ✅ Excellent cross-compilation
- ✅ Small download (~60MB)
- ❌ Less common in C++ projects
- ❌ Potential C++ compatibility issues

## Comparison with Zig

[Zig's approach](https://ziglang.org/learn/overview/) bundles everything:
- LLVM backend
- libc implementations for all platforms
- Custom linker for Apple Silicon
- Self-hosted compiler

Our approach is similar but uses:
- Homebrew LLVM (or system clang)
- Hermetic Linux sysroots (Bazel downloads)
- Standard LLVM linker (lld)
- Existing Redpanda build system

## Benefits

1. **Speed**: Setup in 5 minutes vs hours
2. **Simplicity**: One command to install toolchain
3. **Maintenance**: `brew upgrade` vs rebuild/upload
4. **Flexibility**: Works with Homebrew, system clang, or custom builds
5. **CI-Friendly**: GitHub Actions macOS runners have Homebrew

## Trade-offs

1. **Local Installation Required**: Users must install Homebrew LLVM (or use system clang)
2. **Version Variability**: Different developers may have different LLVM versions
3. **Not Hermetic**: Unlike downloaded toolchains, local paths may vary

## Mitigations

1. **Document Minimum Version**: Require LLVM 20+
2. **Provide Setup Script**: Automate installation and configuration
3. **Support Multiple Sources**: Homebrew, system clang, or custom builds
4. **CI Uses Consistent Version**: Pin LLVM version in CI

## Future Options

If hermetic, downloaded toolchains are needed later:

1. **Build and Upload**: Use `bazel/toolchain/build-macos-toolchain.sh`
2. **Use LLVM Major Releases**: When official macOS builds are available
3. **Host on GitHub Releases**: As originally planned

For now, the Homebrew approach provides the best developer experience.
